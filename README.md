# panel for YPtun

Русскоязычная панель для VPN-служб на одном Linux-сервере. Python 3.9+, Docker Engine / Compose v2, OpenSSL; Python/npm-зависимости не нужны. Форматы генераторов сверены с [YPtun](https://github.com/yanisplugg/yptun/tree/2a8f9517fa9a62fa2f50dcf1e57b41cec8c6d0cc).

История версий и изменений: [CHANGELOG.md](CHANGELOG.md).

```sh
cd yptun-panel
python3 -B server.py
# Запуск контейнеров на этом же хосте:
YPTUN_ALLOW_DOCKER=1 python3 -B server.py
```

Первый запуск печатает случайный путь, логин `admin` и пароль. Они сохраняются: пароль — PBKDF2-SHA256-хеш с 600000 итерациями в `data/panel.sqlite3`. Панель по умолчанию слушает `127.0.0.1:8080`. Для VPS используйте systemd и HTTPS reverse proxy из `deploy/`. Поле адреса службы задаёт адрес для клиентов, оно не подключает другой сервер по SSH.

## Установка и обновление через curl

На Linux с работающим systemd и установленными Bash и curl выполните:

```sh
sudo bash -c 'set -o pipefail; curl -fsSL https://raw.githubusercontent.com/Rehby/panel/main/deploy/install.sh | bash' </dev/tty
```

Ввод `sudo` подключён к терминалу, чтобы запрос домена/IP работал и при настройке sudo с псевдотерминалом. При выполнении от root можно убрать `sudo`.

Одна и та же команда устанавливает панель или обновляет её до текущего коммита `main`. На Debian/Ubuntu установщик добавляет недостающие пакеты через apt, включая Python 3.9+, Docker, nginx с HTTP/2, certbot, sudo, OpenSSL, Git и системные утилиты. Существующий Docker не заменяется. При отсутствии Compose v2 устанавливается проверенный по SHA-256 официальный плагин для x86_64 или arm64 (его нужно обновлять вручную). Для других дистрибутивов или архитектур необходимые компоненты следует установить вручную. Установщик проверяет systemd, HTTP/2 и службы `docker`, `nginx`, `certbot.timer`.

При запросе введите домен или публичный IP панели без `https://` и нажмите Enter: установщик ждёт ввод из терминала. После ввода он показывает этапы установки и вывод системных команд в консоли; выпуск сертификата может занять несколько минут. В конце выводятся URL, логин и пароль. Сохраните пароль: повторно его показать нельзя. Для домена используется Let's Encrypt; DNS должен указывать на сервер, порты 80 и 443 должны быть доступны. Для IP создаётся самоподписанный сертификат, которому нужно доверять на устройстве. Существующие конфигурации nginx не должны конфликтовать; панель слушает только localhost за HTTPS reverse proxy. Если выпуск сертификата не удался, устраните причину и повторите установку — логин и пароль сохранятся. При обновлении существующая HTTPS-настройка и пароль сохраняются; запрос адреса повторяется только если HTTPS ещё не настроен.

Обновление предназначено для штатной установки в `/opt/yptun-panel` с данными в `/var/lib/yptun-panel`: оно сохраняет настройки, учётные данные, подписки и VPN-контейнеры. Панель ненадолго останавливается; перед обновлением создаётся резервная копия SQLite в `/var/backups/yptun-panel`, а прежний код остаётся в `/opt/.yptun-previous-*`. При ошибке установщик пытается восстановить прежнюю версию и базу. Нестандартные расположения данных и исходники, содержащие `data/`, автоматически не обновляются. Следите за свободным местом для резервных копий.

Если в штатной конфигурации nginx отсутствует маршрут `/subscription/`, обновление добавляет его по образцу локального `/turn-sub/`, проверяет конфигурацию и перезагружает nginx. Нестандартный маршрут необходимо настроить вручную.

Версия задаётся в `VERSION`, а при установке также сохраняется точная ревизия Git. На странице обзора отображаются версия, загрузка CPU, память, диск, uptime и load average. Показатели доступны в Linux и обновляются каждые пять секунд; при недоступности отображается ошибка, а не нулевое значение.

## Службы и автоматическая настройка

| Движок | Необходимый ввод | Выдача и отзыв |
|---|---|---|
| VLESS | Сервер; транспорт и Reality/TLS; при TLS используется сертификат панели | Отдельные UUID, Reality-ключи создаются автоматически |
| VMess / Trojan | Сервер; при TLS используется сертификат панели | Отдельные UUID / пароли |
| Telegram · WebProxy | Сервер tgwebproxy | HTTPS / WebSocket, отдельная ссылка `tg://webproxy`, без подписки |
| Shadowsocks | Сервер | Один пароль на службу |
| Hysteria2 | Сервер, сертификат панели | Отдельные пароли, опциональная Salamander |
| Mieru | Сервер; диапазон TCP/UDP-портов | Отдельные пароли, ссылка `mierus://`; закреплённая сборка mita из исходников |
| WireGuard / AmneziaWG | Сервер | Серверные ключи, отдельные пиры и IP, AWG 2.0 параметры автоматически |
| VK-TURN / qWDTT | Сервер и общие VK-хеши звонков | Штатный Admin API, до 10 подписок на туннель |
| VK-TURN / Free TURN | Сервер; при выдаче VK-хеши звонков | WireGuard-backend, пиры, ключ обфускации автоматически |
| olcRTC | Сервис звонков, комната, транспорт | Ключ и YAML автоматически; одна выдача на службу |
| MasterDNS | Сервер и DNS-домен | TOML, AES-256-GCM ключ и клиентский resolver автоматически; одна выдача на службу |
| OpenFlux | Площадка; для cups.online ссылка необязательна, для остальных нужна ссылка документа / комнаты | Команда, общий AES-ключ и share-link автоматически; одна выдача на службу |
| TrustTunnel | Сервер, сертификат панели | Серверные TOML, отдельные учётные записи, `tt://` ссылки |
| snolc | Сервер | Noise-ключи, builtin-модули и TOML автоматически; одна выдача на службу |
| WARP | Сервер | Вход VLESS + Reality с отдельными UUID, выход через приватный WARP SOCKS |
| Свой Xray / sing-box JSON | Образ, серверная конфигурация и соответствующий клиентский профиль | Ручное управление ключами в конфигурации |

Название службы и нового подключения подставляется по протоколу; для VLESS в него также входят Network и отметка SELF при self-SNI. По публичному IP или DNS-адресу службы автоматически определяется страна, её флаг добавляется к названию. Панель скачивает и хранит ежемесячную базу DB-IP Lite локально ([IP Geolocation by DB-IP](https://db-ip.com)); проверяемые адреса не передаются в API геолокации. Определение приблизительное. Если страна не определена или проверка ещё выполняется, можно сохранить название без флага либо указать двухбуквенный код вручную. Название можно изменить вручную, существующие службы и подключения не переименовываются. Адрес текущего сервера и свободный внешний порт тоже подставляются. Все новые внешние порты, включая прямой MasterDNS, выбираются случайно в диапазоне 10000–65535 с проверкой TCP/UDP и назначений панели. Кнопка позволяет выбрать другой порт. Существующие порты сохраняются. Внутренние порты контейнеров и клиента задаются по требованиям движков.

Для транспорта Xray Hysteria панель создаёт общий ключ транспорта и включает его в серверную и клиентскую конфигурации. После обновления перезапустите существующую службу с этим транспортом и обновите клиентский профиль или подписку.

У MasterDNS прямой resolver `сервер:случайный_порт` включён в профиль. Для работы через сторонние рекурсивные DNS нужна DNS-делегация и доступный авторитетный порт 53; этот режим требует отдельной сетевой настройки.

Движки с общим ключом используют одну выдачу на службу: отзыв последнего доступа останавливает контейнер. Это предотвращает ситуацию, когда запись исчезает из подписки, а её ключ продолжает работать. Для другого подключения создайте отдельную службу. Комнаты звонков, доступ к сторонним площадкам и DNS-записи предоставляет администратор; панель генерирует конфиги и секреты, но не создаёт учётные записи у провайдеров. Исключение — комнаты cups.online для OpenFlux: при пустой ссылке они создаются без учётной записи через встроенный мастер предварительно собранного образа. Список комнат сохраняется для перезапуска и профиля; доступность и срок жизни комнат зависят от площадки.

Если комнаты cups.online закрылись, очистите ссылку в настройках службы и сохраните её для создания новых комнат. После этого обновите подписку или передайте пользователю новый профиль.

Готовые образы скачиваются Docker при запуске. olcRTC, OpenFlux, qWDTT и snolc собираются кнопкой в разделе «Образы» из закреплённых ревизий. snolc использует vendored-бинарник YPtun со встроенными модулями, а не несовместимый upstream-загрузчик `.so`. Сборки не запускают VPN-службы.

Ранее импортированные службы сохраняют свой конфиг и ручной режим. Панель не обещает автоматически отзывать ключи из произвольного импортированного конфига. Для новой службы используется генератор; свободный JSON остаётся отдельным режимом.

## Пользователи и общая подписка

Создайте пользователя → нажмите «Выдать», отметьте службы и сохраните → передайте один адрес `https://домен/subscription/<случайный_токен>`. Снятие галочки удаляет соответствующее подключение и ключ после подтверждения. Для импортированных конфигураций и старых TURN-служб без общей VK-ссылки используйте ручную настройку; ключ импортированного движка нужно отозвать также в его конфигурации. При ошибке пакетного изменения панель сообщает число выполненных операций: перед повтором откройте список заново. Службы можно создавать и запускать отдельно. У пользователя может быть несколько подключений одного или разных протоколов.

Профили и адреса подписки скрыты до нажатия «Показать текст». Их можно скопировать, скачать в файл или показать как QR-код; QR создаётся локально в браузере. Для слишком больших конфигураций используйте скачивание файла. Показывайте QR и передавайте файлы только владельцу доступа: они содержат секреты.

Общая подписка вычисляется заново при каждом запросе: JSON с `links`, включая универсальные `yptun://inbound?v=1&d=…` для сложных профилей. Она сохраняет полные Xray-настройки транспортов, AWG и параметры qWDTT. Отключённые и истёкшие доступы, а также подключения остановленных через панель служб исключаются. После запуска службы её действующие подключения снова появляются без смены ключей и адреса подписки. Учитывается заданное в панели состояние, а не кратковременная недоступность Docker. Старые индивидуальные подписки остановленной службы временно возвращают 404. Ответ запрещает кеширование и рекомендует обновление раз в час; клиент обновляет подписку сам или по команде пользователя. Изменение имени или состава подключений не меняет адрес. Смена адреса инвалидирует только прежний токен, а не VPN-ключи.

При обновлении старые доступы автоматически превращаются в пользователей, без смены их ключей и токенов. Старые `/sub/<токен>` и `/turn-sub/<токен>` продолжают работать. Неподдерживаемый импортированный профиль не ломает остальные подключения: общая подписка возвращает его в `unavailableProfiles` с пояснением.

## TURN: лимиты и редактирование

qWDTT управляется в разделе «Службы»; VK-TURN / Free TURN также остаётся доступен как отдельный вариант. qWDTT 1.4.3 использует штатный лимит 10 подписок. Отключённые подписки тоже занимают место; истёкшие очищаются ядром. Панель показывает занятость, блокирует заполненные варианты в выборе и предоставляет кнопку с поясняющим попапом. Перед созданием лимит повторно проверяется на сервере под блокировкой. Само ядро также ограничивает число записей.

VK-хеши / ссылки звонков (до 4) задаются в настройках службы и автоматически применяются ко всем её пользователям. При изменении они обновляются и у ранее выданных подключений. Старые службы без общей ссылки сохраняют индивидуальные хеши, пока ссылка не задана в настройках службы. Хеши также можно хранить в библиотеке. По умолчанию выдаётся доступ на 30 дней и одно устройство. При редактировании без срока прежняя дата сохраняется. Продление удалённого ядром истёкшего доступа создаёт новый пароль в прежней подписке пользователя.

Работающее ядро изменяется через отдельный локальный HTTPS Admin API с проверкой собственного сертификата. При остановленном контейнере панель редактирует runtime-базу атомарно, сохраняя резервную копию. При `running`, `restarting`, `paused` или невозможности проверить состояние прямая запись базы запрещена. Секретные токены Admin API не попадают в подписки. qWDTT короткая ссылка имеет совместимую с YPtun схему `qwdtt://config`.

## HTTPS и self-SNI

По умолчанию TLS-службы используют сертификат панели и её домен или IP в SNI. При продлении сертификата связанные службы обновляются автоматически; смена адреса панели требует сначала отвязать службы от её сертификата. Самоподписанному IP-сертификату необходимо доверять на устройстве. Можно отдельно выпустить сертификат службы или загрузить собственный PEM; ранее настроенные сертификаты сохраняются.

Для VLESS RAW/TCP, XHTTP и gRPC + Reality можно включить self-SNI: используется свой домен с настроенным HTTPS и локальный сайт nginx на `127.0.0.1:9443`. Домен и ключи настраиваются автоматически. Все сочетания транспортов и безопасности ограничены возможностями Xray и клиента; устаревшие транспорты не подставляются вместо новых.

Случайный путь администратора сохраняется при обновлениях. Публичные подписки не раскрывают его. Сессии на 12 часов: HttpOnly, SameSite=Strict и Secure при HTTPS, Origin-проверка изменений, отзыв при выходе. После 10 неверных попыток вход блокируется для IP на 15 минут. Панель доступна извне через настроенный HTTPS reverse proxy.

## Эксплуатация и проверка

Переменные: `YPTUN_DATA`, `YPTUN_HOST`, `YPTUN_PORT`, `YPTUN_ALLOW_DOCKER=1`, `YPTUN_HTTPS=1`, `YPTUN_OPENSSL`. `YPTUN_ADMIN_USER` / `YPTUN_ADMIN_PASSWORD` применяются только при первом создании учётной записи в базе. Логин, пароль и сессии авторизации хранятся в `data/panel.sqlite3`; при обновлении панели с более старой версии, хранившей их в `auth.json`/`sessions.json`, данные переносятся в базу автоматически, а старые файлы удаляются.

SQLite и секреты хранятся в `data/` (0700), конфиги — 0600; экспортные ZIP содержат ключи. Используйте SQLite backup API или остановку панели для резервной копии. Серверные процессы могут менять владельца runtime-файлов; панель не меняет права на чужие файлы глобально.

Изменение доступов перезапускает только затронутую работающую службу; это может кратко разорвать её подключения. При сбое сохраняются прежние данные и выполняется попытка восстановить контейнер. Остановка Python-панели не останавливает VPN-контейнеры. Статус Docker `running` не подтверждает внешнюю доступность или прохождение трафика через VK/другую площадку.

```sh
python3 -B -m unittest discover -s tests -v
node --check static/app.js
node tests/test_share.js
```

Тесты проверяют генераторы, совместимые форматы, миграцию, устойчивый адрес подписки, изоляцию пользователей, отзыв, откат, лимиты TURN, offline-редактирование и HTTP-авторизацию. `deploy/verify-live.py` и дополнительные smoke-скрипты создают временные объекты для проверки установленной панели; пароль читается через TTY. Для реального теста сторонних транспортов нужны действительные комнаты и совместимый YPtun-клиент.

### WebProxy для Telegram

Соберите образ Telegram WebProxy в разделе «Образы». Создайте службу «Telegram · WebProxy» с отдельным доменом, отличным от адреса панели. DNS домена должен указывать на сервер; TCP 80 и 443 должны быть доступны. Выдайте пользователю доступ и запустите службу. Установленная Linux-панель автоматически выпустит сертификат Let's Encrypt и добавит HTTPS/WebSocket vhost nginx. При обновлении панели устанавливается и обновлённый HTTPS helper.

В «Пользователи → Подключения → Профиль» доступны кнопка «Добавить в Telegram», копирование ссылки и QR-код. Формат: `tg://webproxy?server=proxy.example.com&secret=0123456789abcdef0123456789abcdef`. Нужен клиент Telegram с поддержкой типа WEB. Ссылка не содержит внутренний порт: клиент подключается по HTTPS 443.

Каждый доступ получает отдельный случайный 16-байтовый secret. Его можно заменить в настройках подключения. Отзыв удаляет secret из конфигурации и перезапускает сервер; при отзыве последнего доступа служба останавливается. Прокси исключены из общей подписки YPtun и не выдаются через `/sub/`.

Используется [tgwebproxy](https://github.com/kesevone/tgwebproxy), закреплённый на ревизии `44aa88ac176ee89a9bf8cdf1b76227d8c653f2a1`. Внутренний HTTP-порт публикуется только на `127.0.0.1`; nginx проксирует все пути, поддерживает WebSocket и не пишет URL с bridge-токенами в access log. Удаление службы удаляет её vhost. При локальном запуске без Linux HTTPS helper доступна генерация файлов; для запуска с автоматическим HTTPS нужна установленная панель.

### Образы

Раздел «Образы» сохраняет проверку, повторное скачивание и сборку. В дополнительных настройках каждой службы есть поле «Docker-образ»: можно указать совместимый образ или другой тег. Пустое поле использует стандартный образ. У работающей службы сохранение настроек пересоздаёт контейнер. Для WARP переопределяется образ WARP, а его вход Xray остаётся штатным; Free TURN переопределяет образ Free TURN, сохраняя WireGuard-backend.

### Трафик и лимиты пользователей

В разделе «Пользователи» показаны отправленный, полученный и общий трафик. Дополнительно доступны показатели «Сегодня», «Всё время» и текущие счётчики движков. Сброс расхода для лимита сохраняет дневную и общую историю; день определяется по локальному времени сервера. Кнопка «Трафик и лимит» позволяет задать общий лимит в ГиБ (1 ГиБ = 1024³ байт), где 0 означает отсутствие лимита, или сбросить накопленный расход. Расход суммируется по всем подключениям владельца, включая удалённые, и сохраняется до ручного сброса. Автоматического ежемесячного сброса нет.

Учёт поддерживается для WDTT/qWDTT, Telegram WebProxy, VLESS, VMess, Trojan, Shadowsocks, управляемого WARP и автоматически настроенных WireGuard, AmneziaWG и Free TURN. Для импортированных конфигураций и остальных движков выводится «Учёт недоступен». При смешанном наборе подключений отображается неполный расход; установить лимит можно после удаления подключений без учёта. Добавление такого подключения пользователю с лимитом запрещено.

Сбор статистики и проверка лимитов работают в фоне независимо от открытого браузера. Между циклами — 10 секунд; опрос движков и применение конфигураций занимают дополнительное время, поэтому возможен перерасход. Счётчики сохраняются в SQLite, обычное пересоздание служб предварительно сохраняет последнюю статистику. При аварийной остановке движка может потеряться расход после последнего успешного опроса. Ошибка получения статистики отображается как отсутствие свежих данных.

При достижении лимита ключи пользователя исключаются из конфигураций и подписок. Работающие службы пересоздаются, что может ненадолго прервать подключения других пользователей этой службы; после блокировки последнего активного доступа служба останавливается. Сброс расхода, снятие или увеличение лимита снимают блокировку и восстанавливают остановленную лимитом службу. Ручное отключение доступа или остановка службы сохраняются. Если Docker не применил ограничение, интерфейс показывает ожидающее применение и ошибку; панель повторяет попытку.

Для действующих служб Xray и WebProxy после обновления панель один раз включает счётчики с пересозданием контейнеров. WDTT использует уже встроенные счётчики без пересоздания службы. WebProxy отдаёт метрики через локальный Unix-сокет, Xray API доступен только на loopback внутри контейнера (при host network — на loopback хоста); дополнительных публичных портов статистики нет.

### Счётчики WDTT/qWDTT

Реализация сверена с [WDTT Control Panel](https://github.com/lebrit/wdtt-control-panel/blob/20ac69db1345948f50a06a72f4526436d4734145/wdtt_panel/app.py#L539). Поля `up_bytes` и `down_bytes` qWDTT 1.4.3 учитывают трафик устройств владельца в WireGuard и RAW-режимах. Панель читает их через локальный защищённый API `/admin/passwords` и записывает прирост в SQLite. Для чтения этих счётчиков стороннее расширение и пересборка образа не нужны.

Счётчики ядра сохраняются в `passwords.json`, поэтому перезапуск контейнера не начинает новый отсчёт в панели. Уменьшение счётчика или смена пароля обрабатываются отдельно без потери накопленной истории. При первом импорте уже накопленный трафик входит во «Всё время» и в расход для лимита, но не в «Сегодня»: дата старого трафика неизвестна. При временной недоступности API показывается ошибка, а сохранённые значения не заменяются нулями.

Лимит остаётся общим для владельца по всем подключениям. Для WDTT его применение вызывает `/admin/passwords/deactivate`: ядро закрывает соединения пароля, отключает его устройства и удаляет WRAP-ключ. Остальные пользователи и служба продолжают работать. Сброс или увеличение лимита активирует только те доступы, которые не были отключены вручную. Это ограничение проверяет панель с интервалом опроса; расширение ядра с собственными пакетами трафика из эталонной панели не устанавливается.

### Обновления образов

При открытии раздела «Образы» панель запускает проверку версий в фоне. Результат каждого образа, включая ошибку проверки, кешируется на 24 часа в `data/image-updates.json` (на установленном сервере — `/var/lib/yptun-panel/image-updates.json`). Повторное открытие вкладки в течение суток использует кеш. Кнопки «Проверить обновления» и «Проверить все обновления» запрашивают сведения заново независимо от кеша. Без открытия вкладки новых проверок по расписанию нет.

При обнаружении обновлений появляется счётчик возле раздела «Образы» и уведомление в шапке панели. Карточки показывают время последней проверки, новую версию или ревизию и ошибки доступа к реестру/репозиторию. Ошибка новой проверки не скрывает ранее найденное обновление, но для обновления потребуется повторная успешная ручная проверка.

Для Xray и sing-box проверяется последний стабильный GitHub-релиз и наличие соответствующего образа в реестре. Предварительные версии и понижение версии не выбираются. Для остальных готовых образов сравнивается содержимое тега в реестре с локальным образом. Для сборок из исходников сравнивается HEAD репозитория с OCI-меткой установленной ревизии. Проверка не скачивает слои, не собирает образы и не запускает контейнеры. Поддерживаются Buildx и штатная команда Docker manifest для установок без Buildx.

Кнопка «Обновить» скачивает образ по проверенному digest либо собирает конкретную найденную ревизию исходников в отдельный тег. После успешного обновления связанные работающие службы автоматически пересоздаются с новым образом; панель проверяет запуск нужной версии. Остановленные службы не запускаются, а службы с собственным основным образом сохраняют его. Выбранная версия сохраняется между перезапусками панели. При ошибке сборки остаётся прежняя версия. При ошибке запуска выполняется попытка отката всех уже затронутых служб к прежним конфигурациям и фактическим ID образов; ошибка восстановления явно показывается в журнале операции. Кнопки повторной сборки и скачивания также сохранены.

Уведомления относятся к штатному каталогу. Службы с явным полем «Docker-образ» и импортированные собственные конфигурации сохраняют свои образы; их версию меняют отдельно в настройках службы. Новые ревизии сторонних исходников могут изменить совместимость: журнал неудачной сборки доступен в карточке образа.

Промежуточные Docker-образы без тегов старше суток автоматически очищаются после успешной сборки или обновления и ежедневно через `yptun-image-cleanup.timer`. Кеш сборки старше недели очищается с сохранением до 512 МБ. Образы с тегами, образы существующих контейнеров и Docker volumes сохраняются. Ошибка очистки после сборки записывается в `cleanup_error` операции и не отменяет успешную сборку.
