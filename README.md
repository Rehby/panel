# panel for YPtun

Русскоязычная панель для VPN-служб на одном Linux-сервере. Python 3.9+, Docker Engine / Compose v2, OpenSSL; Python/npm-зависимости не нужны. Форматы генераторов сверены с [YPtun](https://github.com/yanisplugg/yptun/tree/2a8f9517fa9a62fa2f50dcf1e57b41cec8c6d0cc).

История версий и изменений: [CHANGELOG.md](CHANGELOG.md).

```sh
cd yptun-panel
python3 -B server.py
# Запуск контейнеров на этом же хосте:
YPTUN_ALLOW_DOCKER=1 python3 -B server.py
```

Первый запуск печатает случайный путь, логин `admin` и пароль. Они сохраняются: пароль — PBKDF2-SHA256-хеш с 600000 итерациями в `data/auth.json`. Панель по умолчанию слушает `127.0.0.1:8080`. Для VPS используйте systemd и HTTPS reverse proxy из `deploy/`. Поле адреса службы задаёт адрес для клиентов, оно не подключает другой сервер по SSH.

## Установка и обновление через curl

На Linux с systemd заранее установите Python 3.9+, curl, Docker Engine с Compose v2, nginx, certbot, sudo и OpenSSL. Нужны команды `useradd`, `usermod`, `runuser`, `visudo` и службы `docker`, `nginx`, `certbot.timer`. Для шаблона nginx требуется версия с поддержкой `http2 on`. На сервере выполните:

```sh
set -o pipefail
curl -fsSL https://raw.githubusercontent.com/Rehby/panel/main/deploy/install.sh | sudo bash
```

Одна и та же команда устанавливает панель или обновляет её до текущего коммита `main`. Установщик скачивает архив конкретной ревизии по HTTPS. При первой установке запишите выведенные путь, логин и пароль; после этого настройте HTTPS для домена, указывающего на сервер, например:

```sh
printf '%s\n' '{"host":"vpn.example.com","mode":"domain"}' | sudo /usr/local/sbin/yptun-https
```

Для выпуска сертификата должны быть доступны порты 80 и 443; существующие конфигурации nginx не должны конфликтовать. Панель начинает слушать только localhost. HTTPS также можно настроить через интерфейс при наличии безопасного доступа к нему.

Обновление предназначено для штатной установки в `/opt/yptun-panel` с данными в `/var/lib/yptun-panel`: оно сохраняет настройки, учётные данные, подписки и VPN-контейнеры. Панель ненадолго останавливается; перед обновлением создаётся резервная копия SQLite в `/var/backups/yptun-panel`, а прежний код остаётся в `/opt/.yptun-previous-*`. При ошибке установщик пытается восстановить прежнюю версию и базу. Нестандартные расположения данных и исходники, содержащие `data/`, автоматически не обновляются. Следите за свободным местом для резервных копий.

Если в штатной конфигурации nginx отсутствует маршрут `/subscription/`, обновление добавляет его по образцу локального `/turn-sub/`, проверяет конфигурацию и перезагружает nginx. Нестандартный маршрут необходимо настроить вручную.

Версия задаётся в `VERSION`, а при установке также сохраняется точная ревизия Git. На странице обзора отображаются версия, загрузка CPU, память, диск, uptime и load average. Показатели доступны в Linux и обновляются каждые пять секунд; при недоступности отображается ошибка, а не нулевое значение.

## Службы и автоматическая настройка

| Движок | Необходимый ввод | Выдача и отзыв |
|---|---|---|
| VLESS | Сервер; транспорт и Reality/TLS; при TLS кнопка выпуска сертификата | Отдельные UUID, Reality-ключи создаются автоматически |
| VMess / Trojan | Сервер; при TLS кнопка сертификата | Отдельные UUID / пароли |
| Shadowsocks | Сервер | Один пароль на службу |
| Hysteria2 | Сервер, кнопка сертификата | Отдельные пароли, опциональная Salamander |
| WireGuard / AmneziaWG | Сервер | Серверные ключи, отдельные пиры и IP, AWG 2.0 параметры автоматически |
| VK-TURN / qWDTT | Сервер; при выдаче VK-хеши звонков | Штатный Admin API, до 10 подписок на туннель |
| VK-TURN / Free TURN | Сервер; при выдаче VK-хеши звонков | WireGuard-backend, пиры, ключ обфускации автоматически |
| olcRTC | Сервис звонков, комната, транспорт | Ключ и YAML автоматически; одна выдача на службу |
| MasterDNS | Сервер и DNS-домен | TOML, AES-256-GCM ключ и клиентский resolver автоматически; одна выдача на службу |
| OpenFlux | Площадка и ссылка документа / комнаты | Команда, общий AES-ключ и share-link автоматически; одна выдача на службу |
| TrustTunnel | Сервер, кнопка выпуска сертификата | Серверные TOML, отдельные учётные записи, `tt://` ссылки |
| snolc | Сервер | Noise-ключи, builtin-модули и TOML автоматически; одна выдача на службу |
| WARP | Сервер | Вход VLESS + Reality с отдельными UUID, выход через приватный WARP SOCKS |
| Свой Xray / sing-box JSON | Образ, серверная конфигурация и соответствующий клиентский профиль | Ручное управление ключами в конфигурации |

Название, адрес текущего сервера и свободный внешний порт подставляются. Все новые внешние порты, включая прямой MasterDNS, выбираются случайно в диапазоне 10000–65535 с проверкой TCP/UDP и назначений панели. Кнопка позволяет выбрать другой порт. Существующие порты сохраняются. Внутренние порты контейнеров и клиента задаются по требованиям движков.

У MasterDNS прямой resolver `сервер:случайный_порт` включён в профиль. Для работы через сторонние рекурсивные DNS нужна DNS-делегация и доступный авторитетный порт 53; этот режим требует отдельной сетевой настройки.

Движки с общим ключом используют одну выдачу на службу: отзыв последнего доступа останавливает контейнер. Это предотвращает ситуацию, когда запись исчезает из подписки, а её ключ продолжает работать. Для другого подключения создайте отдельную службу. Комнаты звонков, доступ к сторонним площадкам и DNS-записи предоставляет администратор; панель генерирует конфиги и секреты, но не создаёт учётные записи у провайдеров.

Готовые образы скачиваются Docker при запуске. olcRTC, OpenFlux, qWDTT и snolc собираются кнопкой в разделе «Образы» из закреплённых ревизий. snolc использует vendored-бинарник YPtun со встроенными модулями, а не несовместимый upstream-загрузчик `.so`. Сборки не запускают VPN-службы.

Ранее импортированные службы сохраняют свой конфиг и ручной режим. Панель не обещает автоматически отзывать ключи из произвольного импортированного конфига. Для новой службы используется генератор; свободный JSON остаётся отдельным режимом.

## Пользователи и общая подписка

Создайте пользователя → выдавайте ему подключения к любым созданным службам → передайте один адрес `https://домен/subscription/<случайный_токен>`. Службы по-прежнему можно создавать и запускать отдельно. У пользователя может быть несколько подключений одного или разных протоколов. Можно изменить метку, UUID/пароль подходящего протокола, VK-хеши, срок TURN, перевыпустить WG-ключи, включить, отозвать или удалить подключение.

Профили и адреса подписки скрыты до нажатия «Показать текст». Их можно скопировать, скачать в файл или показать как QR-код; QR создаётся локально в браузере. Для слишком больших конфигураций используйте скачивание файла. Показывайте QR и передавайте файлы только владельцу доступа: они содержат секреты.

Общая подписка вычисляется заново при каждом запросе: JSON с `links`, включая универсальные `yptun://inbound?v=1&d=…` для сложных профилей. Она сохраняет полные Xray-настройки транспортов, AWG и параметры qWDTT. Отключённые и истёкшие доступы, а также подключения остановленных через панель служб исключаются. После запуска службы её действующие подключения снова появляются без смены ключей и адреса подписки. Учитывается заданное в панели состояние, а не кратковременная недоступность Docker. Старые индивидуальные подписки остановленной службы временно возвращают 404. Ответ запрещает кеширование и рекомендует обновление раз в час; клиент обновляет подписку сам или по команде пользователя. Изменение имени или состава подключений не меняет адрес. Смена адреса инвалидирует только прежний токен, а не VPN-ключи.

При обновлении старые доступы автоматически превращаются в пользователей, без смены их ключей и токенов. Старые `/sub/<токен>` и `/turn-sub/<токен>` продолжают работать. Неподдерживаемый импортированный профиль не ломает остальные подключения: общая подписка возвращает его в `unavailableProfiles` с пояснением.

## TURN: лимиты и редактирование

qWDTT 1.4.3 использует штатный лимит 10 подписок. Отключённые подписки тоже занимают место; истёкшие очищаются ядром. Панель показывает занятость, блокирует заполненные варианты в выборе и предоставляет кнопку с поясняющим попапом. Перед созданием лимит повторно проверяется на сервере под блокировкой. Само ядро также ограничивает число записей.

VK-хеши / ссылки звонков (до 4) можно хранить в библиотеке. По умолчанию выдаётся доступ на 30 дней и одно устройство. При редактировании без срока прежняя дата сохраняется. Продление удалённого ядром истёкшего доступа создаёт новый пароль в прежней подписке пользователя.

Работающее ядро изменяется через отдельный локальный HTTPS Admin API с проверкой собственного сертификата. При остановленном контейнере панель редактирует runtime-базу атомарно, сохраняя резервную копию. При `running`, `restarting`, `paused` или невозможности проверить состояние прямая запись базы запрещена. Секретные токены Admin API не попадают в подписки. qWDTT короткая ссылка имеет совместимую с YPtun схему `qwdtt://config`.

## HTTPS и self-SNI

Сертификаты выпускаются по кнопке: домен — Let’s Encrypt с автопродлением, IP — самоподписанный сертификат с необходимостью настроить доверие на устройстве. Также доступен собственный PEM. Сертификаты VPN-служб хранятся отдельно от сертификата панели, renewal-hook обновляет только связанные службы.

Для VLESS RAW/TCP, XHTTP и gRPC + Reality можно включить self-SNI: используется свой домен с настроенным HTTPS и локальный сайт nginx на `127.0.0.1:9443`. Домен и ключи настраиваются автоматически. Все сочетания транспортов и безопасности ограничены возможностями Xray и клиента; устаревшие транспорты не подставляются вместо новых.

Случайный путь администратора сохраняется при обновлениях. Публичные подписки не раскрывают его. Сессии на 12 часов: HttpOnly, SameSite=Strict и Secure при HTTPS, Origin-проверка изменений, отзыв при выходе. После 10 неверных попыток вход блокируется для IP на 15 минут. Панель доступна извне через настроенный HTTPS reverse proxy.

## Эксплуатация и проверка

Переменные: `YPTUN_DATA`, `YPTUN_HOST`, `YPTUN_PORT`, `YPTUN_ALLOW_DOCKER=1`, `YPTUN_HTTPS=1`, `YPTUN_OPENSSL`. `YPTUN_ADMIN_USER` / `YPTUN_ADMIN_PASSWORD` применяются только при первом создании `auth.json`.

SQLite и секреты хранятся в `data/` (0700), конфиги — 0600; экспортные ZIP содержат ключи. Используйте SQLite backup API или остановку панели для резервной копии. Серверные процессы могут менять владельца runtime-файлов; панель не меняет права на чужие файлы глобально.

Изменение доступов перезапускает только затронутую работающую службу; это может кратко разорвать её подключения. При сбое сохраняются прежние данные и выполняется попытка восстановить контейнер. Остановка Python-панели не останавливает VPN-контейнеры. Статус Docker `running` не подтверждает внешнюю доступность или прохождение трафика через VK/другую площадку.

```sh
python3 -B -m unittest discover -s tests -v
node --check static/app.js
node tests/test_share.js
```

Тесты проверяют генераторы, совместимые форматы, миграцию, устойчивый адрес подписки, изоляцию пользователей, отзыв, откат, лимиты TURN, offline-редактирование и HTTP-авторизацию. `deploy/verify-live.py` и дополнительные smoke-скрипты создают временные объекты для проверки установленной панели; пароль читается через TTY. Для реального теста сторонних транспортов нужны действительные комнаты и совместимый YPtun-клиент.
